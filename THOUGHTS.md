# THOUGHTS — Things Heard, Observed, Unclear, Guessed, Hacked, Tracked, or Suspected : A living document about non-trivial details

This document will serve as a scratchpad for things encountered during development.  
You will find here notes about undocumented stuff, questions about implementation, random ideas that don't fit quite yet the PLAN, ...  
Developpers and Agents alike can write here freely so knowledge never gets lost. Some things can stay in a conversation, in an LLM inner Chain-of-Thoughts, in reasoning, ... but what if we start a new thread ? Everything gets lost. `THOUGHTS.md` fixes that, by providing a persistent, searchable record of non-trivial details that Agents and Developpers can write into and refer to.  
Information already present elsewhere (README, AGENTS, PLAN, PROGRESS, plans folder, docs, code & comments, ...) shouldn't be duplicated here.

## 2026-08-14 — Unknown model — Codex Desktop — "Investigate Task 7 export failures"

- The first full export proved that sharing `.output/public` with an ordinary Nuxt build can erase an in-progress publication; ordinary builds now target `.output-live`, and export must keep publishing from isolated staging with rollback rather than restoring a shared output path.
- A raw Codex `turn_id` is not necessarily unique within one rollout: steering messages sent while the model is working are inserted into the active turn and can reuse its ID. Across the original 46 failed sources, all 147 repeated raw-ID groups represented multiple substantive, distinct viewer turns rather than copied rows; preserve the raw ID as correlation metadata but give each normalized turn occurrence its own stable identity instead of dropping or blindly merging repeated IDs.
- Repeated activity IDs need type-aware handling: 270 web-search groups were `web_search_end`/`web_search_call` views of one call and six tool groups were call/output halves that should be losslessly paired, while the one repeated plan ID held two different plan revisions and needs separate occurrence identities. A generic duplicate-row drop or merge would lose real conversation data.
- Export failures for a source that never reaches a retained normalized session are only returned as transient `cache.unavailable` diagnostics, so the persisted cache and `doctor` can report zero parser diagnostics even after a real export failure. Preserve source-level failure evidence independently of successful session rows.
- Node's `readline` treats U+2028 and U+2029 inside JSON string values as line boundaries even though `JSON.stringify` does not escape them, so Pagefind's JSONL spool must be decoded on ASCII LF only or valid records can split mid-string.
- The no-index export is the only accepted full-archive path so far: 522 sessions published atomically in 417 seconds and `doctor` reported 522 sessions, zero parser diagnostics, and search disabled. The native Pagefind run retained a roughly 1 GB/11,000-record spool, consumed extreme memory, and still failed to finish within an hour; treat indexed export as unaccepted and never resume or relaunch that workload without an explicit new performance strategy and user approval.
- A sandbox that permits repository writes but denies the viewer cache under `%LOCALAPPDATA%` produces a misleading blanket failure: unchanged sessions remain readable, changed sources become `cache.unavailable`, and all rich-content cache updates fail with `attempt to write a readonly database`. Re-run the direct PNPM no-index export with normal LocalAppData write access before diagnosing session content.
- The genuine full-archive run has 19 rich-content fallbacks, all from `resolveFavicon` rejecting HTTP(S) link origins whose host is an IP literal; the conversations are valid, but favicon validation currently aborts their entire rich-content preparation. Reporting now keeps these individually identifiable and separate from unpublished ingestion failures; a future fix should retain the link and skip/default only its favicon.
