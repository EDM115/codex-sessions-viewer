# THOUGHTS — Things Heard, Observed, Unclear, Guessed, Hacked, Tracked, or Suspected : A living document about non-trivial details

This document will serve as a scratchpad for things encountered during development.  
You will find here notes about undocumented stuff, questions about implementation, random ideas that don't fit quite yet the PLAN, ...  
Developpers and Agents alike can write here freely so knowledge never gets lost. Some things can stay in a conversation, in an LLM inner Chain-of-Thoughts, in reasoning, ... but what if we start a new thread ? Everything gets lost. `THOUGHTS.md` fixes that, by providing a persistent, searchable record of non-trivial details that Agents and Developpers can write into and refer to.  
Information already present elsewhere (README, AGENTS, PLAN, PROGRESS, plans folder, docs, code & comments, ...) shouldn't be duplicated here.

## 2026-08-13 — Unknown model — Codex Desktop — "Implement Plan Task 3 ingestion boundaries"

- On Windows, one Chokidar v5 instance combining existing session directories with exact metadata paths that do not yet exist can suppress directory change events; keep the active-session, archive, and exact-metadata watchers independent unless a replacement is verified against the live append test.
- Nuxt's production SSR build generated an unresolved `entry-styles-*.mjs-!~{...}~.js` placeholder when the custom Rolldown `manualChunks` function forced Vue/Nuxt packages into vendor chunks; the build passed after removing that function, so do not restore equivalent chunking without verifying `pnpm build` and `pnpm export`.
- Nuxt's experimental `buildCache` can prevent Vitest projects created through `defineVitestProject` from resolving: restoring a cached Nuxt build may skip the `vite:configResolved` hook, so Node exits successfully without collecting tests. Keep `experimental.buildCache: false` in the Vitest-only Nuxt overrides unless a later Nuxt/test-utils version is proven to emit the hook on cache restoration.
- Validate that a file-backed cache is exactly an unlinked `viewer.sqlite` before constructing `DatabaseSync`: connection setup such as `journal_mode=WAL` can mutate a database before migrations get a chance to reject it, and a correctly named hard link can otherwise target Codex's `state_5.sqlite`.
- Rollout turn, message, activity, and raw-event IDs are session-local and repeat across transcripts, so viewer-cache keys and foreign keys must remain composite on `(session_id, id)` even when a fixture set appears globally unique.
- Persist source mtime from the same verified stable-read observation used for the exact hash, then compare it with the post-read path observation; taking mtime only from a later stat can pair an old hash with a newer same-size rewrite and incorrectly trust it on the next scan.

## 2026-08-14 — Unknown model — Codex Desktop — "Investigate Task 7 export failures"

- The first full export proved that sharing `.output/public` with an ordinary Nuxt build can erase an in-progress publication; ordinary builds now target `.output-live`, and export must keep publishing from isolated staging with rollback rather than restoring a shared output path.
- A raw Codex `turn_id` is not necessarily unique within one rollout: steering messages sent while the model is working are inserted into the active turn and can reuse its ID. Across the original 46 failed sources, all 147 repeated raw-ID groups represented multiple substantive, distinct viewer turns rather than copied rows; preserve the raw ID as correlation metadata but give each normalized turn occurrence its own stable identity instead of dropping or blindly merging repeated IDs.
- Repeated activity IDs need type-aware handling: 270 web-search groups were `web_search_end`/`web_search_call` views of one call and six tool groups were call/output halves that should be losslessly paired, while the one repeated plan ID held two different plan revisions and needs separate occurrence identities. A generic duplicate-row drop or merge would lose real conversation data.
- Export failures for a source that never reaches a retained normalized session are only returned as transient `cache.unavailable` diagnostics, so the persisted cache and `doctor` can report zero parser diagnostics even after a real export failure. Preserve source-level failure evidence independently of successful session rows.
- Node's `readline` treats U+2028 and U+2029 inside JSON string values as line boundaries even though `JSON.stringify` does not escape them, so Pagefind's JSONL spool must be decoded on ASCII LF only or valid records can split mid-string.
- The no-index export is the only accepted full-archive path so far: 522 sessions published atomically in 417 seconds and `doctor` reported 522 sessions, zero parser diagnostics, and search disabled. The native Pagefind run retained a roughly 1 GB/11,000-record spool, consumed extreme memory, and still failed to finish within an hour; treat indexed export as unaccepted and never resume or relaunch that workload without an explicit new performance strategy and user approval.
- A sandbox that permits repository writes but denies the viewer cache under `%LOCALAPPDATA%` produces a misleading blanket failure: unchanged sessions remain readable, changed sources become `cache.unavailable`, and all rich-content cache updates fail with `attempt to write a readonly database`. Re-run the direct PNPM no-index export with normal LocalAppData write access before diagnosing session content.
- The genuine full-archive run has 19 rich-content fallbacks, all from `resolveFavicon` rejecting HTTP(S) link origins whose host is an IP literal; the conversations are valid, but favicon validation currently aborts their entire rich-content preparation. Reporting now keeps these individually identifiable and separate from unpublished ingestion failures; a future fix should retain the link and skip/default only its favicon.

## 2026-08-15 — GPT-5 — Codex Desktop — "Fix live startup and full no-index export"

- The reported live failure and the 19 previously isolated full-archive rich-content fallbacks have the same boundary defect: a valid conversation link whose origin is an IP literal reaches favicon resolution and the SSRF guard aborts conversation preparation. Keep the network guard strict, but degrade favicon enrichment per origin so the link and conversation remain usable.
- The 576-session `--no-index` `RangeError: Invalid string length` came from message inspector generation copying every raw record in the owning turn into every message record; one real session has 89,193 raw events and 5,829 messages, so the multiplicative JSON exceeded V8's string limit. Message inspectors must select only `message.rawEventIds` while retaining owning-turn metrics; turn inspectors remain the complete raw-evidence view.
- Live reconciliation exceeded a roughly 5 GB heap because unchanged-source checks eagerly materialized full cached conversations and the incremental updater retained every parsed JSONL record graph for future appends. Use lightweight cache reads for fingerprints/rich-content checks, avoid retaining live source graphs, coalesce watcher batches, and let touched-but-content-identical sources update only their manifest mtime after a stable SHA verification.
- The live HTTP shell must not await archive reconciliation: open the queryable viewer database first, render the read-only loading skeleton on the first HTML request, then begin reconciliation after that response and expose preparing/ready/error state through the loopback status API.
- Nuxt prerender cannot consume generated JSON merely because it was copied to an isolated public input directory. Serve that private directory through a static-mode-only, traversal-checked `/payloads/**` handler during generation, publish the same files after Nuxt completes, and prerender only the explicit route manifest; crawling archived conversation links can invent invalid routes such as the literal `/session/.*`.
- Final real-data acceptance on 576 sessions completed `pnpm export --no-index` with 2 transformed, 574 reused, 0 failed, and 0 rich-content fallbacks; `doctor` reported 513 active plus 63 archived sessions with search disabled. The independently unaccepted indexed Pagefind workload remains out of scope.

## 2026-08-15 — GPT-5 — Codex Desktop — "Implement Plan Task 12 release readiness"

- Static Pagefind filters must use session-wide summary values to match live search, and Windows `cwd` filter values need an opaque encoded key: Pagefind advertises raw backslash-bearing values but does not successfully query them. Preserve the raw cwd only in result data, encode it consistently when indexing and filtering, and exercise the generated Pagefind browser API instead of mocking search results.
- Keep Pagefind integration in its own non-parallel Vitest project on Windows. Running it beside other workers can collide during Pagefind's atomic index rename even when the search code is correct; separating only that project preserves parallelism for the rest of the suite.
- Task 12 output verification is a publication-boundary check, not another export implementation: validate payload topology, chunk/navigator/inspector consistency, local asset integrity, symlink/hard-link safety, and the absence of external automatic HTML/CSS resources one session at a time so the verifier remains viable for hundreds of sessions.
- Do not use the real 576-session archive to satisfy Task 12's indexed `pnpm export --offline` gate. The prior native Pagefind run was not accepted and exhausted extreme memory; indexed acceptance must use representative fixtures until the user explicitly approves a new full-archive strategy.
- The first elevated Task 12 production build processed 2,468 client modules and emitted several JavaScript chunks above Vite's 500 kB warning threshold (the largest was roughly 790 kB raw and 200 kB gzip). Treat this as a measured optimization lead, not proof of a specific culprit: map the output chunks to source dependencies, establish route-load behavior and a repeatable before/after baseline, and keep only optimizations that exceed run-to-run noise while preserving the release gates.
- The dominant measured payload cost is activity/raw protocol evidence rather than the application bundle: the current real static snapshot contains roughly 855 MB of turn JSON and 2.1 GB of inspector JSON, with single chunks up to 21 MB and 88 MB. Count-only 20-turn chunking cannot bound this, and collapsed native details still cost SSR/payload/DOM unless their descendants are conditionally rendered or their detail data is fetched separately.
- Live repository reads must stay query-bounded: parsing every cached turn and raw event before slicing was 28.5 times slower than bounded SQL on the 500-turn fixture. Navigator, chunk, and inspector reads now select only their required rows, and static inspector payload version 2 pools each raw event once per chunk; keep corruption tests proving unrelated rows are not decoded.
- Do not enable `retainLiveSources` as a shortcut for append speed: the retained normalized graphs would approach the full archive size in memory. Incremental live append needs a bounded checkpoint/tail architecture before that optimization is safe.

## 2026-08-16 — GPT-5 — Codex Desktop — "Design lazy live catalog and grouped conversation workspace"

- A fast live landing page needs a catalog boundary separate from normalized conversation payloads: discovery plus optional state/session-index metadata can supply counts, archive state, cwd/project, parent edges, and list summaries without parsing every transcript. Materialize only the visible 20-session page in one bounded batch, force materialization when opening an uncached session, and re-normalize watcher changes only for already-hot sessions; otherwise the existing deferred reconciliation merely moves the same full-archive cost behind the first HTML response.
- `LibraryExplorer` currently copies `useAsyncData("library-initial")` into local refs before a client-navigation payload necessarily resolves and never reapplies the eventual result. That is why offline counts and rows reset to zero when returning from a session and become correct only after a scope toggle triggers an explicit refresh; keep the library query state above route components or watch/apply the async payload rather than snapshotting it once.
- Current Codex guardian rollouts can put tens of kilobytes of base instructions in the first `session_meta` JSONL record, so a strict 4 KiB catalog prefix may intentionally have no complete JSON value even though the top-level parent ID is already present. Keep startup byte-bounded: classify these rows from the retained `state_5.sqlite` model (`codex-auto-review`) and extract only the early unescaped `parent_thread_id` hint rather than expanding every source read.
- A metadata refresh must not replace a same-revision ready catalog summary with its cold zero-count approximation. Preserve content-derived models, counts, tool totals, previews, and media flags while overlaying mutable catalog metadata such as title, scope, pin/section state, and topology.
- On Windows, Nuxt build-cache artifacts can retain absolute `C:/...` module IDs from a live build and restore them into a later static build as invalid `c:` ESM imports. Keep Nuxt build caching enabled for live builds but disable it for isolated static export generation.
