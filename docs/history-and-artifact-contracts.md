# History, archives and artifact contracts

The live and static repositories share typed catalog, history, presentation and asset contracts. The current cache schema is 8, source-generation/normalization parser is 13 and native item adapter is 5. The Zstd JSONL envelope admission contract is v2. Static session indexes and library catalogs use version 2, saved source-qualified history manifests use version 1. These numbers describe different contracts, none is a claim that an old archive has been revalidated against its original source.

## Library and deliberate search

Metadata readiness reads state/JSON/index metadata through viewer-owned snapshots. With usable metadata, it performs no rollout enumeration, stat, prefix/body read, decode, normalization or rich-content preparation. Native history copying and validation are background work started by selected history, they do not gate the metadata response. Metadata-only browsing, group expansion, scope switching and title/project search keep that boundary. Metadata recovery is a separate qualified path when those sources are unavailable.

Project identity is the native ID and supplying host scope, not a filesystem path. Explicit projectless membership, native projects and populated Sections have distinct typed group identities, including IDs such as `none`. Explicit projectless choices survive Git/cwd metadata. Ambiguous legacy mappings remain unresolved. Ordinary library rows are visible roots, delegated children expand under their parent, Guardian and internal Security helper chats are excluded.

Transcript search is a deliberate operation over indexed content. Starting indexing prepares eligible missing sessions, reports partial coverage and unavailable sessions, and supports cancellation. A query or selection change fences late job responses. Global transcript search can return a delegated-child-only match with parent navigation (the ordinary library root contract does not suppress those deliberate content hits). The same typed membership filter applies to live cached search, index candidates and static Pagefind results.

Static version 2 search resolves eligible session IDs from the saved typed catalog, applies Pagefind's explicit `session: { any: [...] }` filter, then hydrates only the requested result page. Plain arrays mean AND in Pagefind 1.5.2, so the explicit `any` is part of the contract. The selected-page defensive filter remains, older version 1 unscoped archives preserve their existing cursor and malformed-hit behavior. See [Pagefind's compound filtering API](https://pagefind.app/docs/js-api-filtering/#using-compound-filters).

Generated static routes and the loopback offline server allow `'wasm-unsafe-eval'` for the local Pagefind engine. The live policy remains unchanged, neither policy allows JavaScript `'unsafe-eval'` or external script/connect origins. This distinction follows [Pagefind's hosting requirements](https://pagefind.app/docs/hosting/) and [the CSP WebAssembly directive](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src#unsafe_webassembly_execution).

## Source generations and history

Stable thread, root session, physical rollout, turn, item, call and Code Mode cell identities remain separate. A physical source path, size or timestamp cannot validate content. Plain selected pages carry verified decoded ranges, a tail read does not establish a full-stream digest. Deliberate indexing/export verifies complete source generations and required ancestor cutoffs. Compressed sources are decoded into viewer-owned generation-specific files, encoded and decoded fingerprints stay separate. Reopening an existing compressed cache requires digest validation, equal-size/equal-time replacement still invalidates dependent normalization, rich content, search and exports.

Selected native history uses a copied, validated SQLite generation. The worker copies, recovers the private copy, runs `quick_check`, verifies required indexes and hashes the copy. The source database is never opened by SQLite. Native point item lookups require a `thread_id, turn_id, item_id` index. Projection watermarks qualify covered prefixes, they are not content digests or a universal complete changefeed. Mixed/multi-segment updates retain range-refetch fallback. Native item preparation, raw approval evidence and rich media are separate lazy operations.

History pages expose coverage, gaps, preparation and opaque owner-qualified cursors. Recent turns and older items inside a huge turn load separately. A separately recovered opening prompt is not implicitly adjacent to a loaded tail. Missing ancestors, unsupported records, malformed/unfinished data and stale generations remain qualified. An explicit final phase or completion-backed original message determines the final pointer, later commentary does not silently become the final answer.
Cursor-free live latest pages (including navigator requests) may reread once after a typed history reload conflict, with fresh selection and every source, range, dependency and publication guard rerun under the same query, cancellation signal and selected-work lifetime. Each attempt retains the selected-read limits, the maximum cost is two attempts. Cancellation or disposal prevents the reread, a second conflict still returns HTTP 409, and item, cursor, before, after, explicit-turn and other error behavior remains unchanged.  
Explicit older, target and item-preparation requests can resolve superseded physical ancestry independently of the catalog's selected row, enumerate at most 4096 directory entries per discovery slice, and resume unfinished discovery on another request. A completed discovery map serves every ancestor in one lineage operation and is refreshed at the next operation boundary, candidate paths never replace fresh metadata or byte verification. Boundary preparation reads cancellable 64 KiB chunks under the existing segment and decoded-byte limits. The first recent plain-leaf page does not require this scan or ancestor decompression. Cursor recovery after ancestry discovery still revalidates the issued boundary and source ranges, it cannot authorize changed bytes.  
Each selected live SSE connection owns observation of its exact plain/Zstd representation family and already resolved dependencies. Shared selections retain one observer until the final connection closes, idle views remain subscribed, concurrent selections remain independent. The observer samples file metadata once per second and publishes invalidation (never content proof), no unselected rollout enumeration or source probe is added to metadata readiness. Reads still validate source generations and ranges. Navigator updates retain a deliberately paged slice within the same epoch, discard obsolete epochs and expose recoverable failures.  
Core and legacy message mirrors require adjacent source-family evidence, compatible supplied identity and phase. Equal prose alone cannot delete a message, original and mirrored records remain Inspector evidence. Supported native review notifications remain admitted across plain and Zstd envelopes, while the first decoded session identity remains mandatory.

The mounted timeline retains at most 60 turns and 300 items/review records per retained turn. Rich results and failed rich keys are independently capped at 128, rich formatting/highlighting/Mermaid concurrency is 2/2/1 with bounded queues. These are cardinality and scheduling policies, not a total heap or byte ceiling. One source item, saved AST or selected Inspector record can still be large. Reader input cancels pending navigation ownership, an actual reading-entry anchor survives growth within a turn, and distant targets remain retained until positioning finishes. Follow intent requires vertical input that can reach the outer scroller and actual outer movement (or a qualified outer boundary gesture), nested consumption and owned corrections cannot re-arm it. A source-qualified anchor restore that is clamped or waiting for its retained entry to mount remains incomplete and retains its desired offset with the paired surface geometry until an existing layout event can settle it, reader input, navigation, disposal or invalidated ownership releases it. Entry eviction requires retained logical-data authority, missing DOM or unknown payloads cannot prove eviction. Message alias keys remain stable while their logical owners are retained and are pruned with item, window or source-epoch eviction. Explicit Latest remains a separate bottom-navigation operation.

## Static compatibility and incomplete exports

The version 2 catalog stores metadata and typed groups without invented transcript counters. New exports deliberately read selected source lineage and save source-qualified history/item pages, presentation data and generation provenance. The static reader pages those saved records without reconstructing native ordinals from an older normalized view. Saved presentation queries must match the thread, physical rollout, turn/item, epoch, content revision, Markdown and explicit attachment references.

Version 2 session indexes separately save revision-qualified model, positive tool and media filter facets with `saved-export-observation` authority. Ordinary library queries apply these observations with typed membership before counting and pagination, they do not read conversation bodies. These facets describe the saved normalized records, they do not establish current source completeness. An older index with absent observations or a mismatched content revision remains browsable without those filters, affected filter requests explicitly require regenerating the export instead of silently returning unfiltered results.

Version 1 archives retain their saved legacy representation. Ambiguous legacy project sentinels stay unresolved. An absent history manifest does not cause the reader to fabricate a source-qualified history page. The legacy fallback labels its contents and counts as saved records, with unverified completeness and older inferred outcomes. Raw Inspector evidence remains available where it was saved, regenerating from available source is the path to the current contracts.
Compatibility absence requires explicit not-found semantics (HTTP 404, or ENOENT for a local payload requester). Transport, decoding, schema, ownership and abort failures propagate and failed promises are evicted for retry. Root and embedded child legacy views carry the same saved-record qualification.  
Before publishing any session, export ties the normalized manifest's encoded digest and every logical ancestor dependency to the complete-history generation. A mismatch omits that session with an explicit failed diagnostic before Markdown, legacy/progressive payloads, facets or Pagefind records are written. A later source change cannot mix those already captured representations.

Unsupported records in an otherwise readable export produce partial history and explicit gaps. Malformed/unfinished sources can retain valid legacy records with diagnostics while source-qualified history is unavailable. An unresolvable source or lineage can fail export materialization and is reported in the export summary/diagnostics, it is not silently converted into an empty complete conversation. Generation and publication use isolated staging, a failed publication preserves the previous output.

Each completed session rewrite reconciles the complete generated history artifact set, including the manifest and obsolete successful item chunks. When current history is unavailable, an older manifest cannot survive as an implicit current-history fallback. Reconciliation occurs in generated staging before complete output publication, a failed generation leaves the previous published output coherent.

Native current-rollout references resolve against the selected Codex home, including noncanonical filenames with a valid metadata identity. Only references inside the selected home's sessions/archived_sessions roots are admitted. A plain/compressed representation sibling may resolve the same reference, a distinct physical lineage cannot substitute merely because a filename ID matches. Missing, ambiguous and outside-root declared references produce `source.current_rollout_unresolved` with thread/path/reason provenance in the export summary and CLI, each unresolved declared source counts as failed. The export keeps its reconstructed-conversation publication model, it can publish the remaining available conversations with these explicit omissions. The earlier browser measurements used absolute references, relative/absolute parity and unresolved-reference qualification now have separate actual-export regressions.

## Retained media and external references

Attachment references are observed evidence, they never grant filesystem authority. Selected progressive preparation and static publication use the same bounded classifier and asset store. Default local authority is the selected home's `attachments` directory, additional roots require `--media-root` or explicit settings. Referenced local files must be regular unlinked files, canonical containment must match the configured root, and copied bytes must pass stable-read and type checks. Inline media validates encoding, signature/MIME and resource limits before content-addressed storage.

Generated `image_generation_call.result` PNG bytes are retained independently of a missing `saved_path`. Native/raw user image/audio references survive the progressive adapter. Opening-message media is prepared with its visible rich body, generated work media waits until its work entry is visible. Missing, blocked, invalid and unsupported references stay unavailable, remote images remain explicit links. The full raw-history parser retains its 1 MiB record ceiling, so larger historical inline-image records can remain unsupported even when the decoded image would fit the general media store. The selected presentation envelope is bounded to 6 MiB, each source/Markdown field to 5 MiB and the general media store to 64 MiB. Oversized source references receive an unavailable marker while original raw evidence stays separate, they do not trigger unbounded decoding.

| Recorded representation                                         | Viewer behavior and deletion boundary                                                                                                                                                                         |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inline image bytes                                              | Valid supported bytes are copied into the viewer cache and static assets, deleting an unrelated original image does not remove retained bytes                                                                 |
| Managed local image/audio copy                                  | The exact referenced file can be copied within configured roots, deleting the original outside that managed location does not delete the copy                                                                 |
| Original local path or remote-host path                         | A path alone is not offline bytes, missing/unapproved/inaccessible paths remain unavailable, remote/WSL hosts are not contacted implicitly                                                                    |
| Cloud file ID, `sediment:` reference or Page/artifact reference | Retained as a reference with explicit unsupported/unavailable media state, there is no authenticated cloud downloader                                                                                         |
| Pasted text path and registry excerpt                           | Recorded text/path is preserved, the registry is not scanned to infer attachment ownership and an excerpt is never substituted for a full original pasted file, unsupported file references remain references |
| Security plugin reports and patches                             | Existing recorded content/references remain evidence, no Security explorer or plugin database/helper execution is added, plugin metadata alone does not recover a deleted report                              |
| Visualization HTML                                              | A saved marker/path is not an immutable copy of the HTML, recorded HTML/JavaScript is never executed by this viewer                                                                                           |
| Native thread attachment metadata                               | Task/PR associations remain metadata, they are not treated as a universal index of all composer files or artifact bytes                                                                                       |

An already published archive contains its own verified asset bytes. Later deletion of a source file does not remove that archive copy. A new preparation can report the source missing, a saved cache/archive copy is not proof that the original still exists. The viewer does not scan generated-image folders, plugin report trees or arbitrary transcript paths to expand authority.

## Diffs and source provenance

Recorded file-change items preserve status and exact available evidence. Add/delete content, update hunks and move paths are distinct, a patch invocation records an attempt rather than proving success. Native and correlated failures remain failures even if an outer Code Mode wrapper succeeds, inferred source mentions have unknown outcomes. Full add/delete content can describe that recorded version, update hunks do not establish an entire original file.

The installed Desktop research reference was version 26.1023.6621.0 with archived JavaScript SHA-256 `99ed83950473e34e642f2942226bf40ce9b65e9910afbe8e406120459823c02d`. That bounded source inspection distinguished retained edit items and saved Security patches from transient turn aggregates and current Git/PR comparisons. It did not establish a universal persistent copy of every displayed diff. The authoritative observed Security data subtree was `state/plugins/codex-security`, not the top-level configuration directory. No installed app-server, plugin helper or recorded payload was executed for that research.

## Website enrichment

Favicons and previews are viewer-owned enrichment, not historical message metadata. Selected rich content schedules registered favicon work. `fetchFavicons` keeps its existing default, `fetchLinkPreviews` is a separate opt-in setting. Pointer dwell or keyboard focus requests a bounded preview, Escape dismisses it and touch navigation remains a normal link. Cached preview title/description/imagery remains usable with acquisition disabled. The preview has its own URL, revision and fetch time.

Acquisition validates public destinations, pins approved DNS results across requests and redirects, and bounds headers/body/image bytes, time, types, redirects and work concurrency. Export acquisition requires `--link-previews`, `--offline` disables enrichment transports. Static publication copies only referenced saved metadata and verified imagery. Actual generated pages use same-origin assets and make no automatic external requests. Missing metadata leaves a hostname/Open-link fallback.

The persistent preview cache retains at most 128 results after each saved acquisition (successful or unavailable). Failed requests keep the same 30-second retry policy and share eviction with successful results. Malformed cached JSON cannot block row eviction or unreferenced-image checks, closing the service aborts and drains acquisitions before its caller releases the database.

## Diagnostics and verification boundaries

Doctor reports catalog visibility, unresolved project references, source formats, partial encoded reads, stored generation/decoded sizes and native dependency coordinates. These are labeled saved observations, doctor does not reread every source to make them current. Runtime decode reuse is not fabricated from persisted rows. Generated-output verification checks saved identities, history chunks/presentation ownership, asset hashes, preview imagery and final pointers, structural presence alone is not integrity proof.

Saved evidence sections separately report `available`, `unavailable`, `invalid` or `partial` plus fixed diagnostic reasons for missing tables/columns/rows, invalid payloads and incomplete aggregate inputs. Counters in partial sections describe only decoded observations, counters in unavailable sections do not establish an empty business state. Unresolved project mappings are nullable unless the complete relevant saved project/thread aggregate decodes, a valid empty aggregate reports zero. Doctor JSON retains these qualifications without including private payload content.

Production observations, cache scopes, exact commands and measured limitations are recorded in [performance observations](performance-observations.md). Tests use private fixtures and viewer-owned derivatives. Source immutability is established with actual read/write instrumentation and selected fixture byte/stat checks, not by assuming the user's actively changing Codex home is globally frozen.
