## Additional review corrections

Bounded rich preparation originally restricted guardian ambiguity checks to one page. It now uses an indexed parent-wide input hash, so identical tool calls on different pages remain ambiguous. Removing the last guardian clears stale cached approval evidence. Catalog refresh also checks for database changes across asynchronous prefix I/O, preventing a stale metadata snapshot from overwriting concurrently materialized counts, models, media flags or recovered parent evidence.

The final discriminating review also reproduced a width-resize race: a 1,112px DOM row temporarily occupied a 520px estimated virtual slot. Selecting the first DOM rectangle crossing the viewport replaced the reading anchor with its predecessor, producing a 592px jump. Anchor capture now uses the virtualizer's stable identity and coordinate model while measurements settle. The deterministic regression uses the installed Virtualizer and rejects a disposable copy of the old behavior; browser tolerance remains three pixels.

An old project-identity test gap exposed filesystem-root matching: adding another separator to `/` or `C:\` made descendant paths miss their project. Root-aware containment now preserves the existing directory-boundary rule, with distinct POSIX and Windows regression cases.

## Cache migration and compatibility

Cache schema version 3 adds persisted source metadata evidence, per-turn rich revision markers, final-assistant identity and guardian input hashes. Normalization parser version 5 causes old normalized data to be rebuilt through the normal read-only source path. Source files remain input; changes affect the viewer's derived cache only. Live and static serialization contracts retain compatible optional additions for diagnostics and parent search context.

## Measured warm-path result

The reproducible synthetic benchmark uses Node 26, 500 turns, a 20-turn requested page and 20 sequential samples. The retained run reports median direct bounded reads of 7.3945ms, actual warm repository/reconciler reads of 4.64955ms, and full-session reconstruction of 37.1134ms. Timing varies with concurrent local work; the lower repository time than direct time is measurement noise/warmup, not evidence that the wrapper accelerates SQL. Source and regression tests establish that the warm path no longer reconstructs full history. These timings are a diagnostic comparison, not browser navigation latency or an entire-archive benchmark. Run `node docs/implementation/warm-repository-benchmark.mjs` from the repository root; [the script](warm-repository-benchmark.mjs) writes [its local result](warm-repository-benchmark.json).

## Deliberate limits

- Opening a cold or parser-outdated session still requires a stable source read and normalization. Rich preparation is bounded to requested turns, and warm reads avoid full reconstruction; cold opening is not claimed to be free of source-size cost.
- Incremental append still performs O(history) compact association and summary scans to preserve late tool results, repeated identities, token deltas and provisional turn renaming. The implementation avoids repeated expensive immutable derivation and broad persistence; it does not claim constant-time append processing.
- Source retention is limited to four entries and a 64MiB conservative accounted budget. This is a logical accounting limit, not an instrumented hard JavaScript heap ceiling. Oversized or evicted sessions safely use full reads.
- Guardian auxiliary rollouts are read sequentially within their parent when a tool-bearing page first needs enrichment. A parent with many guardian children can still delay that first page.
- Agent preparation state is not execution state. The child list does not mislabel cold/ready materialization as active/done. Inline lifecycle labels use recorded evidence; absent status remains unknown.
- The original broad intermittent syntax-highlighting complaint was not reproduced as a general parser failure. The confirmed raw-HTML/theme cases and actual browser token colors have specific regression coverage.
- Full-archive export/indexing and pixel-identical Codex cloning are not claimed. Browser and Pagefind tests use bounded local fixtures; real Codex source inputs were not modified.
