# CLI, configuration, contracts, content, and export test review

Reviewed all 27 existing test files in this delegated scope with the discriminating-testing skill. There is no `tests/unit/core` directory or `api.test.ts`; the additionally assigned HTTP API tests are under `tests/integration/live`. UI, ingestion, cache, live service runtime, normalization, metadata, and performance suites are reviewed separately; `liveLauncher.test.ts` and `securityHeaders.test.ts` are included here. This review changes tests only and does not claim whole-project or live-browser acceptance. No Git mutation, build, dependency installation, or whole-archive export was performed.

## Parent integration follow-up

The complete suite passed all 508 tests after this review, but removing the old nonempty default-path checks reduced server/core/paths.ts branch coverage below its existing 90% threshold. The replacement checks exercise the real no-options entry points with distinct process-environment sentinels and assert exact config/cache and Codex-home locations. They distinguish an implementation that ignores the current process environment; the previous injected-options cases could not catch that mistake. The threshold was preserved. Focused paths verification passed 12 tests; the final combined gate is recorded in the implementation report.
