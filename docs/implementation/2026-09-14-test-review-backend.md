## Thought candidates

- A poisoned-row bounded-read test must first prove that its UPDATE matched real rows. Lazy catalog startup can leave the turns table empty, making a corruption-based regression silently vacuous.
- Fresh normalization and static/live parity checks share production logic in places. Preserve them for consistency, but pair them with explicit semantic outputs, actual byte offsets, selected poisoned rows or SQLite write observations when claiming independence.
