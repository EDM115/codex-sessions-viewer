## TypeScript compatibility conclusion

[Microsoft's TypeScript 7 release announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) states that 7.0 has no programmatic API and Vue/Volar workflows must keep the TypeScript6 API. Installed `vue-tsc/index.js` imports Volar and Vue language-core and resolves `typescript/lib/tsc`; installed Nuxt CLI typecheck resolves the `typescript` module and `vue-tsc/bin/vue-tsc.js`. The user's later TS6 exception therefore preserves the supported existing checking path. No TS config migration is needed for this decision. The existing command remains `nuxt typecheck && tsc -p tsconfig.custom.json`.

Update the changed package ranges to the exact targets above using the repository's existing range style, except Node 26 and PNPM 11.26.0. Keep h3 and TypeScript unchanged. ## Thought candidates

Stable-version selection must preserve package identity: h3's historical stable2.0.0 is not the current HTTP framework, and registry latest points at a prerelease. Use supported stable1x=1.15.11 until modern stable2 is released. TypeScript7 can be stable while still incompatible with Vue compiler API integrations; the explicit user TS6 exception resolves this migration constraint without aliases.

## Concrete Vitest 5 migration decisions

1. Root mock configuration becomes effective in all existing inline projects: `clearMocks`, `mockReset` and `restoreMocks` are already true at root. Under Vitest 4 these projects did not specify `extends: true`, so that inheritance is a real behavior change. Prefer preserving the apparent intended cleanup policy and verifying tests. If a test relied on a spy created outside a test or retained calls, move the setup into a hook rather than globally disabling cleanup. Current hoisted mocks are module-level; Mermaid rendering resets in `beforeEach`; stable-read mock fixtures already reset explicitly. The diff mocks retain explicit initial implementations under reset.
2. Shared `#shared` alias is now inherited. Redundant identical alias entries on pagefind/performance/UI may be removed, but that is optional. UI keeps its Vue plugin and own environment; Pagefind must retain `fileParallelism: false` and `sequencer.groupOrder: 1`. The root has no test include override, and [project docs](https://vitest.dev/guide/projects.html) say it is not itself a test project unless explicitly registered: do not add an extra root project or broaden root `test.include`, which could merge into inline includes and defeat their partitioning.
3. Coverage remains a root global setting. Existing config specifies thresholds only: there is no custom `coverage.include` or `coverage.exclude` to migrate and no root `perFile` inheritance to repair. [Coverage documentation](https://vitest.dev/config/coverage.html) says omission includes imported files; adding `server/**/*.ts`, `shared/**/*.ts` or `app/**/*.{ts,vue}` would also add untested files and change the coverage contract. Preserve the current domain unless the user explicitly intends broader enforcement. Record the actual before/after covered-file set, especially child-process integration paths. Keep exact-file 90% branch thresholds.
4. No `bench` imports, `.sequential()` calls, custom assertion types or Vitest browser mode were found in the searched tests. Performance tests are regular tests. `expect.poll` hits belong to Playwright E2E, so Vitest polling migration does not apply there. Existing async assertions must still be validated by execution rather than assuming a text scan proves all are awaited.
5. Vitest's Happy DOM global assignment propagation can change Image/fetch/clipboard behavior in `mediaViewer.test.ts`; execute those tests. No innerWidth/matchMedia assignments were found. `.vitest/` is the new artifact location; add it to `.gitignore` if the upgraded runner produces artifacts (it is not currently ignored).
6. Keep `vitest run --coverage --testTimeout=15000 --maxWorkers=1 --no-file-parallelism`. Prior repository memory identifies Windows short TEMP/TMP watcher crashes and serialized SQLite coverage cleanup constraints; when encountered set TEMP/TMP to the long-form repository `.nuxt` path, and use the exact elevated retry for sandbox readlink failures. This is historical guidance, not a claim that the failure occurs in this upgrade.
