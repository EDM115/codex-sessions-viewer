# Codex Sessions Viewer — Implementation Plan

## Summary

Build a Nuxt 4 and Vue 3 application, managed exclusively with PNPM and running on Node.js, that presents local Codex conversations as a polished, searchable chat archive.

The application has two modes backed by the same typed conversation model and viewer-owned cache:

- `pnpm export` incrementally reads Codex data, generates human-readable Markdown (potentially as Components ?), copies referenced media, builds chunked static payloads, fetches/cache favicons when permitted, prerenders the Nuxt site, and creates an offline Pagefind search index.
- `pnpm live` starts a loopback-only Nuxt/Nitro SSR server, watches Codex data without locking or modifying it, incrementally updates the cache, and refreshes affected browser views through SSE invalidations.
- `pnpm offline` serves the application from the static payloads generated by `pnpm export`, without any live data updates or network fetching.

The source of truth remains the rollout JSONL files. `session_index.jsonl`, global JSON, referenced media, and a validated byte snapshot of `state_5.sqlite` provide metadata enrichment. The viewer must never open the live Codex SQLite database through SQLite, acquire a source-file lock, or create, resume, rename, archive, delete, or otherwise mutate a Codex session.

## Global constraints and locked decisions

- Package manager: `pnpm@11.21.0`, declared through `packageManager`.
- Runtime: Node.js `>=26.7`; never Bun, derined in `package.json`'s engines + devEngines.runtime with onFail:download.
- Framework: Nuxt 4, Vue 3, TypeScript, SSR enabled.
- Bind live and offline servers only to `127.0.0.1`; do not offer a non-loopback host option.
- The application remains fully functional offline. Favicon network fetching is opportunistic and never required for rendering.
- Bundle fonts, icons, Mermaid, syntax grammars, search assets, and all application resources locally; use no CDN or remote font.
- Treat all files under Codex home as immutable and potentially mid-write.
- Never open the live Codex SQLite database through SQLite. Query only a stable viewer-owned byte snapshot.
- Do not acquire advisory or exclusive locks on rollout, index, metadata, SQLite, WAL, or attachment files.
- Write only to viewer-owned cache/config locations and generated output directories.
- Keep app-owned cache and generated directories out of Git.
- Do not stage, commit, branch, push, create worktrees, or perform destructive Git operations.
- Canonical runtime representation: typed normalized data plus cached rich-text AST.
- Markdown is a readable export generated from canonical data, not the runtime source.
- Static referenced media is copied and content-addressed; Codex-owned media is never moved or rewritten.
- Active versus archived status is derived primarily from the selected rollout path under `sessions` or `archived_sessions`, not from a potentially stale database flag.
- Main timeline is curated. Low-level and unknown protocol events remain available through per-message/turn inspectors.
- Default theme: Midnight Glass. Quiet Precision and Editorial Archive are complete selectable themes.
- The UI is viewer-only: no `+` control and no session-creation affordance.
- The selected session uses a subtle background/border, never a stripe on its left.
- Settings is a dedicated `/settings` page opened by a top-right gear icon.
- Compact actions use icons, accessible names, focus states, and tooltips rather than visible text labels.
- Use one icon family throughout application chrome: `@phosphor-icons/vue` in Light or Regular weight with one globally defined visual weight. Favicons and content-provided images are data, not competing UI icon families. Do not hand-draw replacement SVG paths or mix Lucide, Material, Heroicons, emoji, and Phosphor glyphs.
- Use semantic design tokens exclusively for colors, typography, spacing, radii, motion, control sizes, rules, and z-index. Components must not introduce raw colors or one-off font declarations.
- Treat the interface as a dense local developer tool, not a landing page: no hero section, ornamental dashboard cards, fake browser/IDE chrome, marketing footer, scroll theatre, cursor effects, parallax, decorative status dots, or oversized whitespace. However those can be definitely used in an `/about` page that resents the product and act as the "landing page".
- Preserve source transcript typography and punctuation verbatim. Anti-slop copy rules apply only to viewer-owned labels, instructions, empty states, errors, and documentation; they must never rewrite conversation content.

Reference implementation choices against current primary documentation:

- Nuxt static generation and server rendering follow [Nuxt 4 prerendering](https://nuxt.com/docs/4.x/getting-started/prerendering) and [Nuxt deployment](https://nuxt.com/docs/4.x/getting-started/deployment).
- Live browser refresh uses [H3 event streams](https://h3.dev/utils/response), not a WebSocket control plane.
- Static full-text search uses the [Pagefind Node API](https://pagefind.app/docs/node-api/) and locally written browser bundle.
- The cache uses [Node’s built-in SQLite API](https://nodejs.org/download/release/latest-v26.x/docs/api/sqlite.html); the available Node runtime has already been verified to support FTS5.
- The supplied [EDM115 website](https://github.com/EDM115/website) informs the Markdown, Nuxt, code-block, theme, and locally bundled asset approach.
- The supplied [T3Code repository](https://github.com/pingdotgg/t3code) informs timeline virtualization, collapsed work presentation, scroll anchoring, rich Markdown, and message controls only. Do not copy its remote, pairing, orchestration, account, multi-provider, or multi-device architecture.

### Design read and conflict resolution

- Reading this as a single-user local developer tool for Codex users, whose primary job is to find and read long technical conversations safely. The visual language is technical and restrained, with a modern-minimal product shell and a controlled atmospheric treatment only in the Midnight Glass theme.
- Lock the design dials at `DESIGN_VARIANCE=5`, `MOTION_INTENSITY=3`, and `VISUAL_DENSITY=7`. This favors recognizable product structure, immediate state feedback, and compact information density over landing-page spectacle.
- Taste explicitly says its landing-page rules do not govern dashboards or dense product UI. Soft’s mandatory agency treatments, ubiquitous double bezels, magnetic buttons, full-page reveals, huge section spacing, and fluid-island navigation conflict with the viewer’s reading task. Do not implement them. Retain their useful constraints: deliberate type, one icon family, transform/opacity-only motion, restrained blur, named z-layers, and mobile collapse.
- Hallmark’s product-relevant disciplines take precedence over decorative prescriptions: honest copy, locked tokens, no fake chrome, full interaction states, responsive verification, contrast verification, and a final anti-slop audit. Page-only hero/nav/footer gates are marked not applicable rather than simulated.

### Component, state, and accessibility contract

- Build small, focused Vue components with composition over configuration. Separate server/data containers from presentational components and treat approximately 250 lines as a review trigger to split responsibility, not as a mechanical limit. Large components are okay if it's justified and performance is kept in mind.
- Use the simplest owner for state: local `ref` for isolated disclosure/UI state, lifted state for close siblings, typed provide/inject only for stable tree-wide services, URL query state for search/filter/navigation state, Nuxt `useState` for serializable SSR-shared state, and browser storage only for client presentation preferences.
- Composables expose readonly state plus explicit mutation actions, register lifecycle hooks synchronously, and clean up EventSource objects, observers, timers, watchers, and abortable requests with `onScopeDispose`, `onWatcherCleanup`, or equivalent Nuxt lifecycle cleanup. VueUse is your friend for most actions as they avoid writing non-edge-cased logic.
- Use `shallowRef` for large normalized turn chunks and `markRaw` for non-reactive third-party instances where appropriate. Computed getters remain pure; props are never mutated; `v-if` and `v-for` do not share one element.
- Every interactive primitive defines applicable default, hover, focus-visible, active, disabled, loading, error, and success treatments without geometry shifts. Focus rings appear immediately, are 2-3 px, and meet 3:1 contrast against both control and surface.
- Icon-only controls have an `aria-label`, an accessible tooltip, and a visible non-color state change. Hover tooltips wait 800-1000 ms; keyboard-focus tooltips appear immediately, remain hoverable, close on Escape, and never contain the only access to essential information.
- Use native semantic elements first: `<button>`, `<a>`, `<dialog>`, form labels, details/summary, and table semantics. Modal viewers trap focus, mark the background inert, restore focus on close, and support Escape and backdrop dismissal.
- Desktop compact controls may have a 32 px visual box, but coarse-pointer/touch hit targets are at least 44 x 44 CSS px. Hover styling is guarded by `(hover: hover)` and every hover behavior has a focus/tap equivalent.
- Use skeletons for predictable loading layouts, precise empty states that explain why a list is empty, and contextual errors that state what failed and the recovery action. Clipboard success is silent: swap the copy glyph to a check for 2.5 seconds and do not raise a toast.

### Visual system and motion contract

- Create `app/assets/css/tokens.css` as the sole source for `--color-*`, `--font-*`, `--space-*`, `--text-*`, `--radius-*`, `--rule-*`, `--control-*`, `--ease-*`, `--dur-*`, and `--z-*`. Theme files provide complete semantic token values, while component CSS consumes token names only.
- Define theme palettes in OKLCH with tinted near-black/near-white surfaces, verified accent-ink pairs, one decorative accent occupying no more than about 5% of a viewport, and separate semantic success/warning/error/live colors that never rely on color alone. A rule that changes a surface must explicitly provide its matching foreground color.
- Self-host exactly three font families at most: Geist for UI/body/display, Fira Code for code and technical data, and Newsreader as the Editorial Archive display face. Use `font-display: swap`, metric-compatible fallbacks, tabular numerals for timestamps/tokens/durations, roman headings, semantic heading order, and 45-75 character prose measure.
- Use a named 4 px spacing scale, a documented radius hierarchy, and named z-layers for base, raised, in-page sticky, navigation sticky, dropdown, modal, toast, and tooltip. Prefer Grid for page structure and Flexbox for component internals. Avoid card-in-card containment, selected-row side stripes, generic equal-card grids, and shadow-based hierarchy.
- Midnight Glass suggests glass through layered opaque surfaces, restrained highlights, and lightness elevation. Backdrop blur is allowed only on fixed/sticky overlays where it communicates separation and must have a solid reduced-transparency fallback; never blur the scrolling timeline or repeated transcript cards.
- Specify transition properties explicitly; `transition-all` is forbidden. Use the named exponential easing tokens and the 80-150 ms / 180-220 ms / 250-300 ms timing buckets. Animate only opacity and transform, except a narrowly justified accessible disclosure technique. Never animate dimensions, position, spacing, focus rings, scroll position, or virtualized row height.
- Motion must communicate feedback or state change. No automatic section reveals, bounce/overshoot, hover scaling across cards, animated gradients, parallax, magnetic pointer effects, custom cursors, or infinite decorative loops. `prefers-reduced-motion: reduce` collapses spatial motion to an opacity change of at most 150 ms.

### Nuxt, Vue, PNPM, Vite, and Vitest contract

- Keep the Nuxt 4 ownership boundaries: universal types in `shared/`, browser app code in `app/`, server-only ingestion/cache/API code in `server/`, transformed source assets in `app/assets/`, and exact-path generated public artifacts in `public/` only when they must bypass Vite transformation.
- Every exported type & interface in `shared/types/*.ts` will be auto-available in app & server context with auto-imports.
- Use Nuxt-owned primitives for lifecycle and rendering. Initial API data uses `useFetch` or stable-key `useAsyncData` so SSR payloads prevent duplicate hydration fetches; event-driven operations use `$fetch`. Browser-only libraries use `.client` components/plugins or lazy dynamic imports with meaningful SSR fallbacks, not blanket `<ClientOnly>` wrappers hiding hydration defects.
- Configure aliases, Vite, Nitro, runtime config, route rules, and compatibility behavior through `nuxt.config.ts`; do not duplicate Nuxt aliases in standalone Vite or TypeScript config. Add an explicit `compatibilityDate` once, then change it only as a deliberate upgrade. Run `pnpm exec nuxt prepare` after config/module/alias changes.
- Validate every route parameter, query, and body at the H3 boundary with Zod and the matching validated H3 helper. API responses are serializable and client-safe. Server handlers call shared utilities directly instead of making HTTP calls back into the same process. Nitro plugins may own long-lived viewer services but must never store request-specific state in a process-global singleton.
- Use ESM throughout. Vite-specific configuration stays under Nuxt’s `vite` key. Use static asset imports and lazy `import()` boundaries for Mermaid and other large client-only features; never expose server paths or secrets through `VITE_*` or public runtime config.
- Keep this a single-package PNPM application; do not create a workspace or catalogs without a second package. Pin PNPM and Node, preserve PNPM’s isolated dependency model, declare every direct dependency explicitly, keep a frozen lockfile verification step, and allow dependency build scripts only for packages proven to need them, pnpm might create a workspace yaml file to store its settings.
- Split Vitest into a fast Node project for pure ingestion/normalization/cache/serialization logic and a Nuxt environment project for runtime-dependent components/composables. Use Playwright for real-browser end-to-end, accessibility, responsive, clipboard, SSE, and visual behavior rather than duplicating those checks in Vitest browser mode.
- Tests use deterministic clocks and fake timers for debounce/retry/tooltip/copy timing, AbortController-aware mocks for stale-request races, isolated temp fixtures, explicit teardown for watchers/servers/databases, Markdown and normalized-data snapshots for stable serialization boundaries, and behavior-oriented component assertions.

### Command surface

Implement these package scripts:

```text
pnpm live [--codex-home <path>] [--port <number>]
pnpm export [--codex-home <path>] [--output <path>] [--offline] [--force]
pnpm offline [--port <number>]
pnpm run doctor [--codex-home <path>]
pnpm test
pnpm test:integration
pnpm test:e2e
pnpm typecheck
pnpm lint
pnpm format
pnpm build
pnpm coverage
```

Behavior:

- `pnpm live` starts Nuxt SSR, the source watcher, the viewer cache, favicon resolver, and SSE invalidation stream on `127.0.0.1`.
- `pnpm export` performs the full pipeline in one command: scan → normalize → cache → Markdown/media/static data → Nuxt generate → Pagefind.
- `pnpm export --offline` never attempts favicon or other remote requests; it reuses cached favicons and local fallbacks.
- `pnpm export --force` retransforms all sessions while still respecting the source read-only boundary.
- `pnpm offline` serves `.output/public` on loopback.
- `pnpm run doctor` is read-only and reports source discovery, cache status, parser diagnostics, snapshot health, and mode capabilities. The explicit `run` is required because `doctor` is also a PNPM command.

Codex-home precedence:

1. `--codex-home`
2. Viewer-owned configuration
3. `CODEX_HOME`
4. `~/.codex`

Default viewer-owned paths must follow platform conventions:

- Windows: `%LOCALAPPDATA%\codex-sessions-viewer\`
- macOS: `~/Library/Application Support/codex-sessions-viewer/` for config and `~/Library/Caches/codex-sessions-viewer/` for cache
- Linux: `$XDG_CONFIG_HOME/codex-sessions-viewer/` and `$XDG_CACHE_HOME/codex-sessions-viewer/`, falling back to `~/.config` and `~/.cache`

### Task 3 — Implement lock-free source discovery and metadata snapshots

Files:

- Create `server/ingestion/discoverSources.ts`.
- Create `server/ingestion/stableRead.ts`.
- Create `server/ingestion/watchSources.ts`.
- Create `server/metadata/sessionIndex.ts`.
- Create `server/metadata/globalState.ts`.
- Create `server/metadata/stateSnapshot.ts`.
- Add fixtures and integration tests under `tests/integration/source-boundary/`.

Discovery behavior:

- Recursively discover `sessions/**/*.jsonl`.
- Discover `archived_sessions/*.jsonl` and tolerate future nested archive layouts.
- Read `session_index.jsonl`.
- Read selected non-secret global metadata JSON only through named adapters.
- Discover referenced local media lazily from normalized events.
- Never scan or expose authentication, OAuth secret, sandbox-secret, credential, or unrelated plugin files.

Stable-read algorithm:

1. Stat the file (no TOCTOU).
2. Open it with ordinary read-only access and no locking API.
3. Stream only the byte range selected for the current pass.
4. Stat it again.
5. Accept the pass only when identity, size, and relevant modification metadata are compatible with the bytes read.
6. If the file changed, discard the pass and schedule a debounced retry.
7. Preserve an incomplete final JSONL line as pending bytes, not as an error.
8. Treat truncation, replacement, or prefix mismatch as a full-reparse condition.

State snapshot algorithm:

1. Observe `state_5.sqlite` and `state_5.sqlite-wal` stats without opening either through SQLite.
2. Copy them as ordinary bytes into a new viewer-owned generation directory.
3. Re-stat the source files.
4. Discard the generation if either source changed during copying.
5. Open only the copied database using Node SQLite.
6. Enable query-only/defensive behavior on the copy.
7. Run `PRAGMA quick_check`.
8. Query only known columns from `threads`, `thread_sections`, and `thread_spawn_edges`.
9. Ignore the source `-shm` file; allow SQLite to create any required shared-memory state only alongside the app-owned copy.
10. Retain the last validated snapshot when a new one cannot be obtained.

Add concurrency tests with a fixture writer continuously appending while discovery, JSONL reading, index reading, and snapshot attempts occur. Assert that the writer never waits on the viewer and that only the fixture writer changes source bytes, size, and mtime.

Normalization rules:

- Identify sessions by `session_meta.id` or `session_id`; use filename UUID only as a fallback.
- Group events into turns using `turn_context.turn_id`, `task_started`, `task_complete`, abort events, and chronological boundaries.
- Associate response items lacking explicit `turn_id` with the current active turn.
- Deduplicate assistant prose represented in both `event_msg` and `response_item` while retaining raw references to both.
- Pair function/custom/MCP/tool-search calls with outputs by call ID.
- Preserve tool namespace and name separately.
- Derive tool status and duration from explicit events when available; otherwise mark them unknown rather than inventing values.
- Store visible reasoning summaries/text but never attempt to decrypt encrypted reasoning content.
- Normalize web search, patch application, plans, subagent activity, compaction, status, token, media, and error events.
- Preserve all unrecognized top-level and payload event types as `UnknownActivity` with sanitized raw JSON available to the inspector.
- Treat protocol metadata, token-count updates, and turn context as inspector records unless they have meaningful timeline presentation.
- Preserve per-message phase such as commentary/final when present.
- Build per-turn and per-session tool counts by fully qualified tool name.
- Compute answer timestamps from the source event timestamp.
- Compute duration and TTFT only from explicit task metrics.
- Compute token deltas from explicit cumulative snapshots without double-counting.

Metadata precedence:

1. Explicit non-empty `threads.name` from a validated snapshot
2. Latest non-empty `session_index.thread_name`
3. Non-empty snapshot `threads.title`
4. First user-message preview
5. Session ID

For model and reasoning effort, exact per-turn rollout evidence wins over snapshot/session fallback. For active/archive state, the selected stable rollout path wins over database flags. When the same session ID appears in multiple paths during a move, choose the newest stable complete source, emit a diagnostic, and reconcile again after the filesystem settles.

Test every observed event family plus old/new shapes, CRLF/LF, split UTF-8 boundaries, huge individual lines, invalid interior records, partial tails, truncation, duplicated message representations, missing outputs, aborted turns, compaction, parent/child sessions, and unknown future event types.

## Assumptions and explicit defaults

- Windows is the primary acceptance platform, but path handling and viewer-owned directories support Windows, macOS, and Linux.
- Codex rollout schemas may evolve. Unknown events must remain preserved and inspectable rather than causing parser failure.
- `session_index.jsonl` can be stale or incomplete; it enriches rather than gates discovery.
- Codex SQLite state can be stale, corrupt, mid-WAL, or disagree with files. It is optional enrichment only.
- Cached and generated transcripts contain sensitive local conversation content. Use owner-private viewer directories where the platform permits, never add telemetry, and mark generated pages `noindex`.
- Favicon fetching may use the network during export/live mode, but failure never harms rendering and `--offline` disables attempts completely.
- Remote images are not automatically mirrored merely because favicons are fetched. Local and embedded referenced media are preserved; uncached remote images degrade to a safe linked placeholder when offline.
- Clipboard-image APIs are available on secure localhost contexts in supported browsers; unsupported cases remain visibly disabled rather than silently failing.
- The static site is expected to be served locally over HTTP with `pnpm offline`; direct `file://` loading is not an acceptance target because chunked payload/search loading requires a local origin.
- The app has no deployment, account, remote-sharing, synchronization, provider-control, or session-editing scope.
- Implementation remains in the existing checkout with no worktree and no Git writes.
- The fetched Taste and Soft skills are advisory for anti-slop craft, not architectural owners for this product UI. Their React/Tailwind, landing-page, hero, scroll-reveal, magnetic-button, and mandatory double-bezel examples are intentionally not dependencies or acceptance criteria.
- Nuxt owns Vite and SSR configuration; no standalone `vite.config.ts`, custom Vite SSR server, or duplicate alias layer is created unless a verified Nuxt limitation requires it.
- The project remains a single PNPM package. A workspace is introduced only by a future explicit requirement for multiple packages.
- `design.md` is not generated automatically. `tokens.css`, the Hallmark stamp, and the small `.hallmark` preflight/history files are sufficient unless the user explicitly asks to lock/export the design system.
